# DVM Console 0.2.4

Released 2026-08-18. This patch release strengthens lossy P25, DMR, and NXDN receive handling, keeps TAR recordings continuous through recoverable packet damage, stabilizes FNE liveness reporting, and consolidates History into one operator workflow.

## Added

- Add per-frame erasure handling for damaged P25 DFSI records and missing or malformed NXDN voice packets, allowing the stateful vocoder to apply its configured repeat, fade, mute, or comfort-noise behavior.
- Add support for the current dvmhost NXDN FNE layout with its 24-byte message header, modem tags, RF frame, and packet padding while continuing to accept legacy NXDN packets.

## Changed

- Use Console Settings → History as the single full History surface. The Activity header and Tools → Talkgroup Audio Recorder → Viewer open that page instead of a detached Event History dialog.
- Return the Talkgroup Audio Recorder submenu to Tools.
- Reveal recordings in Finder or Explorer with the selected recording highlighted when Open is clicked, rather than sending the file to the operating system's media player.
- Preserve the visible History row while new calls arrive when the operator has scrolled away from the top; History still follows new calls while already at the top.
- Fix P25 tone generation for alerts and signaling.

## Fixed

- Decode the valid P25 IMBE records in a partially damaged LDU and conceal only the unavailable 20 ms slots instead of discarding all nine voice records.
- Keep encrypted P25 keystream position aligned across concealed records and advance encryption state safely when LDU2 ESS records are damaged.
- Conceal bounded NXDN packet gaps and malformed packets through the vocoder, preserve audio timing for playback and TAR, and reset encrypted privacy state after loss.
- Validate NXDN frame sync and LICH before accepting a candidate frame offset so packet padding cannot be decoded as voice.
- Keep P25 calls that carry the FNE placeholder subscriber ID visible in the Activity sidebar and attach their completed TAR recordings.
- Remove sub-frame zero-duration History shells while allowing a later playable TAR finalization to restore the recording-backed row.
- Remove the detached Event History implementation that could crash while connected to an active FNE.
- Initialize the consolidated History viewport only after Avalonia materializes its deferred tab content, preventing a crash when History is opened.
- Require an explicit application-authored PASS result from macOS package smoke testing so LaunchServices cannot mask an application failure.
- Recognize DMR voice LC headers as definitive call starts, preserve them ahead of stale voice in bounded queues, and allow a new header to reopen a legitimately reused stream ID without accepting late voice from the prior call.
- Show green receive status only on channel cards enabled for receive, mirror an active resource across its enabled zone copies, and retain the indication while its queued audio finishes.
- Report bounded UI and per-channel receive queue drops in diagnostics instead of losing them silently.
- Keep isolated malformed-packet diagnostics from falsely faulting a healthy FNE connection, and let the peer monitor repair transient status overrides.

## Validation

The release source passes 535 managed automated tests across Core, FNE, Vocoder, Audio, FNE Client, Media, and Desktop, plus 17 native vocoder unit tests. The unsigned Apple Silicon package passes publish verification and LaunchServices window smoke testing with the converged codeplug. Windows x64 and Intel macOS packages are built and verified by the release workflow; live FNE, vocoder, and audio hardware acceptance remains operator validation.

## Safety and compatibility

DVMHost/FNE R06A00 or newer is recommended. DMR continues to use the three post-FEC AMBE codewords supplied by the FNE packet, and the aggregate DMR FEC diagnostic is not assigned to an individual decoder slot. NXDN 9600/EFR, P25 Phase 2 transport, and per-frame BER exposure remain outside this release. Test with a non-critical FNE and the intended audio hardware before operational use. This software is for personal, non-commercial, amateur, and educational use and must not be used in public-safety or life-safety-critical applications.
