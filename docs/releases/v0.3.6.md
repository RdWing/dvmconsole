# DVM Console *Neo* 0.3.6 — Windows audio and recording-history reliability

Prepared 2026-08-22.

DVM Console Neo 0.3.6 modernizes Windows audio capture and playback, adds optional Windows communications microphone processing, and keeps completed TAR recordings available in History after their live session rows expire.

## Added

- **Optional Windows communications processing.** Windows operators can request device-provided communications effects such as acoustic echo cancellation, noise suppression, and automatic gain control. The available effects depend on Windows, the selected driver, and the endpoint.
- **Stable Windows audio endpoint selection.** Fixed microphone and speaker selections now use stable WASAPI endpoint identifiers.

## Changed

- **Modern Windows audio backend.** Windows capture and playback now use NAudio 3.0.1 shared, event-driven WASAPI instead of the legacy WinMM backend.
- **Existing routing behavior is preserved.** System-default routes continue following the Windows Multimedia-role defaults, fixed routes remain fixed, and a default-microphone change during PTT is deferred until transmit ends.
- **Existing playback behavior is preserved.** Playback queueing, drain handling, starvation diagnostics, and continuous playback remain in place.
- **DVM Console processing remains the default.** Existing microphone gain, equalizer, and automatic gain control behavior is unchanged unless Windows communications processing is explicitly selected.

## Fixed

- **Preserved TAR recordings in History.** Completed TAR recordings remain playable and searchable when their associated live call rows age past the in-memory session limit. They no longer disappear from History until the application reloads the recording catalog.

## Safety and compatibility

DVMHost/FNE R06A00 or newer is recommended. This software is for personal, non-commercial, amateur, and educational use and must not be used in public-safety or life-safety-critical applications.

The current FNE plaintext and legacy encrypted transports are compatibility protocols, not mutually authenticated sessions. Use FNE only across a trusted network or an authenticated VPN.

Settings schema version 6, codeplug compatibility, FNE wire behavior, native vocoder ABI version 7, and macOS Core Audio behavior remain unchanged.

Windows communications processing is opt-in and bypasses DVM Console microphone gain, equalizer, and automatic gain control to avoid applying both processing paths. Its effects are endpoint-dependent, so selecting the mode does not guarantee that every endpoint supplies every effect.

Legacy numeric WinMM device selections cannot be mapped reliably to WASAPI endpoints. A missing legacy fixed selection follows the existing fallback-to-default policy; selecting the device again stores its stable WASAPI endpoint identifier.

Automated release checks do not replace validation with the intended FNE, radio, audio devices, microphone, serial or keyboard PTT hardware, and operator workflow.
