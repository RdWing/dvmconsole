# DVM Console *Neo* 0.3.3 — Built for busy systems

Prepared 2026-08-21.

DVM Console Neo 0.3.3 focuses on receive timing, live-output management, and
clearer operational evidence without changing established channel loudness,
transmit policy, or the TAR capture path.

Adaptive jitter handling now learns independently for each FNE connection and
protocol. New mute scopes suppress only live speaker output, preserving decode,
call state, patching, and TAR. Expanded diagnostics distinguish packet
reordering, missed playout deadlines, decoder delays, mixer pressure, and
physical-output starvation.

| Operator condition | DVM Console Neo 0.3.3 behavior |
| --- | --- |
| Receive network timing varies | Learns an independent, protocol-aligned RX target for each FNE connection |
| Speaker output must be quiet | Mutes live output while decode, patching, call state, and TAR continue |
| RX disruption needs diagnosis | Separates packet order, deadline, decoder, mixer, and physical-output evidence |
| A P25 key arrives after startup | Refreshes the restored secure selection when matching material becomes available |

## Added

- **Adaptive RX jitter handling.** Each FNE connection now has independent,
  packet-aligned P25, DMR, and NXDN jitter buffers. Fixed choices remain
  available, while the default adaptive mode learns from zero through nine
  protocol frames. Every receive stream snapshots one target for the life of
  its call, so adaptation never moves an active call’s playout clock.
- **Speaker-only mute scopes.** New toolbar controls can mute all RX, the
  selected system, or the selected zone. Only live speaker output is
  suppressed: decoding, call state, patches, and TAR recording continue.

## Changed

- **Reduced receive-path scheduling and allocation pressure.** Complete RX
  packets are decoded into caller-owned PCM batches before continuing through
  the receive chain without changing established gain, smoothing, or optional
  processing.
- **Bounded call cleanup.** Receive inactivity now uses one second plus
  one second of grace, with a two-second hold after an explicit terminator.
- **RX-focused History defaults.** Activity Event History shows
  RX-enabled channels by default, with independent `Active`/`All` and
  `Zone Wide`/`System Wide` filters.
- **Coalesced connection health.** Rapid per-packet details give way to readable
  connection-session totals, bounded current-stream summaries, and coalesced
  health updates. Jitter choices sit beside the state-aware Connect/Disconnect
  action, apply immediately, and expose the learned target plus reorder and
  deadline effectiveness counters.
- **Restored reachable window position.** The main console restores its last
  normal size and position when those bounds remain reachable at launch.
- **Bounded session diagnostics.** Debug Logs remain current-session only and
  are capped at 100 MB, discarding the oldest entries first.

## Fixed

- **Packet-aligned live-lane recovery.** An overflowing live RX lane now ages
  only at whole-packet boundaries. TAR retains the complete decoded timeline
  while live output recovers toward current audio.
- **Layered receive diagnostics.** DVM Console detects stalled physical output
  callbacks on macOS and Windows and reports FNE arrival, decoder queue, mixer,
  lane high-water, and device timing as separate evidence.
- **Bounded P25 burst headroom.** Live lanes retain three complete P25
  LDUs so normal packet bursts do not age current speech. RX meters follow the
  selected receive stream while UI lifecycle work catches up.
- **Recording duration is exact.** TAR Ogg Opus recordings now finish with the
  PCM-duration end timestamp instead of advertising codec-frame padding.
- **P25 key requests match established systems.** Unprefixed P25 key IDs are
  interpreted as hexadecimal, and FNE/KMM requests use legacy-compatible
  post-connect settling and per-key pacing.
- **Delayed keys become usable immediately.** When matching FNE/KMM material
  arrives, selectable-encryption controls refresh so a restored secure channel
  presents `SECURE` without another operator action.
- **Narrow settings remain operable.** FNE identity, jitter controls,
  connection actions, microphone-processing values, and AGC controls reflow
  instead of clipping.
- **Busy Debug Logs remain readable.** Incremental virtualization, compact
  rows, stable reading position, and safe recycled-row handling keep the view
  responsive during active traffic.
- **Saved tone timing stays exact.** Valid Alert/QCII pattern steps shorter than
  0.25 seconds are no longer raised to the former preset floor.

## Safety and compatibility

DVMHost/FNE R06A00 or newer is recommended. This software is for personal,
non-commercial, amateur, and educational use and must not be used in
public-safety or life-safety-critical applications.

The current FNE plaintext and legacy encrypted transports are compatibility
protocols, not mutually authenticated sessions. Use FNE only across a trusted
network or an authenticated VPN.

Automated release checks do not replace validation with the intended FNE,
audio devices, microphone, serial or keyboard PTT hardware, and operator
workflow.

For the complete release history, see the
[changelog](https://github.com/RdWing/dvmconsole/blob/neo/CHANGELOG.md).
