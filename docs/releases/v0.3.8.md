# DVM Console *Neo* 0.3.8 — audio path optimization and receive continuity

Prepared 2026-08-23.

DVM Console Neo 0.3.8 is a pure optimization release. It adds no new
workflow, codeplug requirement, or network protocol behavior. Instead, it
tightens receive lifetime, recording playback, audio diagnostics, and PTT
interaction while simplifying the supported macOS microphone path.

## Optimized

- **One standard macOS processing path.** DVM Console processing is now the
  normal macOS microphone path. Apple Voice Processing and the high-quality
  AirPods option are no longer available in Console Settings. A saved Apple
  processing selection is changed to DVM Console processing before any audio
  backend starts.
- **Lower Bluetooth PTT startup overhead.** DVM Console processing avoids the
  additional shared full-duplex route coordination required by Apple Voice
  Processing. The existing microphone-readiness and talk-permit safeguards
  remain in place. Live testing with Bluetooth headsets found less delay before
  transmit readiness. Exact timing remains dependent on the headset, macOS
  route transition, and Keep Mic Warm state, but improvements throughout the
  audio chain mean most headsets should not require Keep Mic Warm.
- **Tail-safe receive finalization.** An ended stream now finishes the packets
  already held by its adaptive jitter worker before its playback and TAR state
  close. This preserves buffered ends of transmissions without merging stream
  IDs or coupling unrelated calls on the same talkgroup.
- **Real-time recording and stream playback.** TAR and web-stream PCM are paced
  against a monotonic media clock. Fast decoding can no longer flood an
  immediately accepting mixer lane, discard most of the audio, and make
  playback appear to start and stop almost at once.
- **Exact level windows.** RX and TX vocoder diagnostics both measure exact
  8,000-sample, one-second PCM windows.

## Fixed

- **Preserve receive tails at timeout.** Audio and TAR teardown no longer runs
  ahead of speech retained by a large adaptive-jitter target.
- **Recover shared output faults.** If a shared output mixer faults, it is
  retired so another client cannot reopen a lane on a permanently stopped
  mixer.
- **Honor mouse toggle PTT.** Clicking a channel-card PTT button now uses the
  same latched mode as the keyboard shortcut. Held and latched states remain
  serialized through slow audio startup and application shutdown.

## Safety and compatibility

DVMHost/FNE R06A00 or newer is recommended. This software is for personal,
non-commercial, amateur, and educational use and must not be used in
public-safety or life-safety-critical applications.

Automated tests and package smoke do not replace live validation with the
intended FNE, radio, microphone, Bluetooth headset, serial or keyboard PTT, and
workflow. Bluetooth PTT and general audio behavior were tested on the
development build; exact device timing and other live protocol or hardware
combinations remain separate acceptance work.
