# DVM Console 0.2.0

Released 2026-08-17. This minor release makes digital-voice support a required, self-contained part of DVM Console, adds NXDN 4800-baud operation, and expands encrypted DMR and NXDN interoperability. It also improves transmit readiness, audio diagnostics, packaging, and day-to-day operator controls.

## Added

- Receive and transmit NXDN 4800-baud clear voice through configured FNE systems.
- Use NXDN EHR, DES, or AES-256 privacy and DMR ARC4, DES-OFB, or AES-256 privacy with protocol-scoped keys from `keys.clear`.
- Inspect call start and end summaries at Info severity and detailed FNE, codec, signal-quality, error-correction, and PCM-level diagnostics at Debug severity. The Debug Logs viewer now opens at Info severity.
- Keep the transmit microphone warm from Console Settings or the main-toolbar microphone control.
- Enable high-quality AirPods input and output explicitly on supported macOS and AirPods combinations.
- Adjust microphone gain, low/mid/high equalizer levels, and the AGC target with 0.1-step controls.

## Changed

- Include the required digital-voice engine in normal builds, tests, and release packages; operators no longer install or place a separate codec library.
- Ship Windows as one self-contained `DvmConsole.exe` with its required native components embedded.
- Generate the FNE software identifier as `DVMC_AV_<version>` from the application version, keeping it synchronized with future releases.
- Play the talk-permit tone only after every selected radio call and the shared microphone path are ready to transmit.
- Acquire high-quality Bluetooth audio only when the operator has enabled it.
- Apply AGC only to transmit capture, expose the full receive-volume range, and provide an adjustable AGC target.
- Reorganize Console Settings and the main menus, use transient settings scrollbars, and center button and field content consistently.

## Fixed

- Preserve DMR and NXDN forward-error-correction results through clear and encrypted receive paths, using loss concealment for uncorrectable voice frames instead of decoding damaged data.
- Keep DMR privacy synchronized across privacy headers and missing frames, and keep encrypted P25 receive fail-closed until valid encryption signaling restores state.
- Remove the retained permit-tone output path that could delay Apple Voice Processing startup while keeping the permit indication tied to actual transmit readiness.
- Keep the warm-microphone enabled state visibly orange, retain FNE connection-pill borders on hover, and prevent the Activity pane from covering the Tones control.
- Restore microphone cleanup when warm-microphone operation is disabled or no longer required.

## Packages

- `dvmconsole-0.2.0-osx-arm64.zip` — Apple Silicon macOS application bundle.
- `dvmconsole-0.2.0-osx-x64.zip` — Intel macOS application bundle.
- `dvmconsole-0.2.0-win-x64.zip` — Windows x64 package containing the self-contained `DvmConsole.exe`.

The packages are self-contained and do not require a separate .NET or Rust installation. Both macOS packages require macOS 14 or newer. All builds remain unsigned.

## Validation

The release source was validated with a clean complete-solution build, 403 managed tests, and 10 native digital-voice tests. Release artifacts should also be exercised with the intended FNE systems, radio modes, encryption keys, and audio hardware before operational use.

## Safety and compatibility

DVMHost/FNE R06A00 or newer is recommended. NXDN 9600/EFR and P25 Phase 2 transport are not implemented. Test the release with a non-critical FNE and the intended audio hardware before operational use. This software is for personal, non-commercial, amateur, and educational use and must not be used in public-safety or life-safety-critical applications.
