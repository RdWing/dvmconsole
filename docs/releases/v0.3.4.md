# DVM Console *Neo* 0.3.4 — Recording and PTT cue reliability

Prepared 2026-08-21.

DVM Console Neo 0.3.4 is a focused reliability patch for two operator paths:
TAR capture that is intentionally independent from live listening, and the
talk-permit indication used by scoped PTT keybinds.

| Operator condition | DVM Console Neo 0.3.4 behavior |
| --- | --- |
| TAR is armed but live RX is not selected | Decodes and records the inbound call without enabling speaker playback |
| The same resource appears on more than one zone card | Keeps recording audio, metadata, and finalization on the TAR-armed copy |
| Global or active-system PTT uses toggle mode | Completes the selected-output talk-permit cue before microphone audio is released |
| A press-and-hold PTT source is released during startup | Finishes the required cue, then stops the call in order |

## Fixed

- **TAR no longer depends on live RX selection.** An armed TAR resource now
  opens its receive decoder and retains the beginning of an inbound call even
  when the corresponding channel card is not selected for speaker playback.
- **Zone copies share one recording decision.** When one card owns the decoder
  and an equivalent card in another zone owns TAR, decoded samples, encryption
  metadata, stream termination, and recording finalization all use the TAR-armed
  card without decoding the network frame twice.
- **Scoped toggle PTT retains its talk-permit indication.** Global,
  active-system, and serial PTT state changes are serialized through microphone
  readiness and cue playback. Toggle mode therefore hears the same local
  transmit-ready tone as press-and-hold mode, while an early release waits for
  startup to finish before stopping the call.
- **Transmit shutdown respects in-flight startup.** Application shutdown waits
  for any active PTT startup and permit cue before disposing their audio
  services.

## Safety and compatibility

DVMHost/FNE R06A00 or newer is recommended. This software is for personal,
non-commercial, amateur, and educational use and must not be used in
public-safety or life-safety-critical applications.

The current FNE plaintext and legacy encrypted transports are compatibility
protocols, not mutually authenticated sessions. Use FNE only across a trusted
network or an authenticated VPN.

Automated release checks do not replace validation with the intended FNE,
audio devices, microphone, serial or keyboard PTT hardware, and operator
workflow. In particular, validate TAR-only receive and toggle-mode talk-permit
behavior against the intended live system and physical audio route.
