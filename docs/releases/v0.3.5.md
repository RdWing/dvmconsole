# DVM Console *Neo* 0.3.5 — Optimization and reliability

Prepared 2026-08-22.

DVM Console Neo 0.3.5 is an optimization and reliability release. It reduces allocation in frequently used audio paths, strengthens reload and shutdown behavior, and reorganizes internal runtime ownership while preserving operator workflows and compatibility.

## Changed

- **Lower allocation in hot audio paths.** Receive routing, vocoder frame assembly, native vocoder calls, and DMR/P25/NXDN transmit packetization now perform less managed allocation while retaining the same output.
- **Clearer runtime ownership.** Settings, desktop sessions, PTT, FNE, audio, playback, and native resources are separated into focused internal components behind the existing public and UI-compatible façades.
- **Stricter automated checks.** Compatibility fixtures, analyzer enforcement, native PCM-ring tests, and packaged macOS smoke coverage strengthen release validation.

## Fixed

- **More reliable codeplug reloads and shutdown.** Activity, PTT, modeless tools, audio services, and background work remain attached to the correct session and shut down in an orderly sequence.
- **Safer concurrent audio lifecycle handling.** Shared microphone startup, transmit state, mixer disposal, and receive-route recovery are serialized consistently.
- **Safer background UI updates.** Web-stream state is dispatched through Avalonia, and intentional background operations are observed for failure.

## Compatibility

- Settings schema version 6, codeplug compatibility, XAML bindings, public façades, FNE wire behavior, 20 ms audio framing, configured gains, routing, jitter, speaker-only mute, TAR behavior, native ABI version 7, and the pinned `fnecore` revision remain unchanged.
- Fixed audio routes still never follow system defaults, and output mute continues to affect speaker presentation without stopping decode, patching, observation, or recording.

## Safety and release acceptance

DVMHost/FNE R06A00 or newer is recommended. This software is for personal, non-commercial, amateur, and educational use and must not be used in public-safety or life-safety-critical applications.

The current FNE plaintext and legacy encrypted transports are compatibility protocols, not mutually authenticated sessions. Use FNE only across a trusted network or an authenticated VPN.

Automated tests, deterministic fixtures, package inspection, and application smoke tests do not replace validation with the intended FNE, radio, microphone, speaker, Bluetooth route, serial or keyboard PTT hardware, and sustained operator workflow. Release acceptance requires the three target packages to pass CI and read-back inspection plus separate live validation on the intended systems.

For the complete release history, see the [changelog](https://github.com/RdWing/dvmconsole/blob/neo/CHANGELOG.md).
