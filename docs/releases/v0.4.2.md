# DVM Console NEO 0.4.2 — Secure voice and live reconfiguration update

This patch release corrects selectable-encryption receive behavior,
brings secure-voice metadata and call-end pacing back onto their protocol
cadence, and makes patch membership changes take effect without restarting DVM
Console. No codeplug, settings, key-file, recording-catalog, or channel-card
migration is required.

## Changed

- Secure DMR transmit sends its privacy header at call startup and carries
  the Association successor message indicator in late-entry fragments plus
  burst-F single-burst algorithm and key identity in the voice superframe. It
  no longer inserts a new privacy header between every superframe. Protected
  group-call link control and the privacy-indicator header carry Association
  FID `0x10`, which is also required when receiving Association privacy
  metadata. The encrypted service option remains set in the voice header,
  embedded link control, and call terminator.
- Padded DMR, P25, and NXDN transmit tails are emitted on their protocol cadence
  before the call terminator instead of being submitted as one burst.
- The NXDN codec carries DES/AES `VCALL` and the current IV in the two FACCH
  halves of one frame. During voice, four-frame SACCH `VCALL` and `VCALL_IV`
  superframes alternate without stealing audio; each advertised successor IV
  is derived by the source-compatible LFSR and becomes active after the eighth
  voice frame of the current encryption session.
- Pending operator settings are flushed before a codeplug load, settings import,
  named-profile change, or settings reset replaces the active session.

## Fixed

- DMR Association ARC4 receive and transmit now discard the first 256 RC4
  keystream bytes at every 18-codeword privacy cycle, keeping Console and radio
  audio aligned under the same key and message indicator.
- Selectable DMR, P25, and NXDN channels now classify receive calls from their
  on-air privacy metadata. **CLEAR** admits clear traffic without requiring the
  configured secure key; **SECURE** is secure-only and rejects clear calls.
- DMR receive classification now distinguishes voice link control, privacy
  headers, voice, embedded link control, single-burst, and reverse-channel
  signaling before decoding payload content. Link-control and privacy metadata
  no longer consume or suppress the first voice packet's sequence number.
- A secure DMR receiver can acquire, when the metadata reaches Console, the
  next-superframe message indicator from the Association C3 wire positions and
  algorithm/key identity from a complete late-entry voice superframe, then
  begin decrypting at the next voice-sync burst. Clear late entry also resolves
  when burst F carries legitimate reverse-channel or other non-privacy
  signaling.
- NXDN voice payloads are no longer forward-error-corrected into phantom FACCH
  call-control messages and silently removed from the audio path. Receivers
  reassemble the alternating SACCH messages, preserve the current IV while its
  successor is being advertised, and can recover DES/AES late entry at the
  following encryption-session boundary. EHR receive also rebuilds its privacy
  processor when a new stream or loss boundary repeats the call metadata.
- Overlapping patch-group saves, enable or disable operations, and decoder
  reconciliation now apply only the newest requested membership. Deselected
  members no longer reappear, and a changed patch no longer requires an
  application restart before it forwards audio. An active source decoder no
  longer blocks unrelated patch-source reconciliation.
- Shared FNE transport writes and microphone-capture lifecycle transitions are
  serialized. Digital call completion has one cadence-preserving asynchronous
  path, preventing concurrent targets or teardown from racing transport state.
- Desktop session replacement prepares the incoming session before committing
  window ownership, then cleans up the outgoing session from a consistent
  ownership state.

## Compatibility and migration

- Existing codeplugs, operator settings, patch memberships, recordings, and
  channel-card layouts remain compatible.
- DMR local key entries remain protocol-specific. DMR Association AES-256 uses
  `protocol: "dmr"` and `algId: 0x05`; P25 AES uses `algId: 0x84`.
- Existing selectable-encryption state is preserved. That state now also acts
  as the receive admission policy: **SECURE** excludes clear calls, while
  **CLEAR** permits clear receive without changing the stored secure settings.

## Known interoperability limits

- `dvmhost r05a06_dev` regenerates DMR embedded data only for voice bursts B
  through E and clears the burst-F single-burst region. Console encodes and
  decodes the algorithm/key identity, but it is not preserved end to end for RF
  late entry through that host revision.
- The same host revision decodes the first valid NXDN startup FACCH half and
  regenerates both RF halves from it. A Console packet containing `VCALL` in
  half 1 and `VCALL_IV` in half 2 reaches RF as two `VCALL` messages, so secure
  NXDN transmit still needs an agreed startup sequence and live radio
  validation.
- These limits do not change selectable receive admission, initial DMR privacy
  header handling, P25 voice, or the patch and settings fixes in this release.
