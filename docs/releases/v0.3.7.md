# DVM Console *Neo* 0.3.7 — patch routing and Apple audio reliability

Prepared 2026-08-23.

DVM Console Neo 0.3.7 makes one-way patch direction explicit, prevents duplicate PCM from reaching patch transmitters, and keeps patch audio on a direct, adaptive-jittered path that is independent from local speaker controls.

## Changed

- **Explicit one-way direction.** Choose the source of a one-way patch directly. Every other selected member is shown as a destination, and existing settings remain compatible by restoring the first saved member as the source.
- **Compact, responsive group editing.** Patch and multi-select cards use two columns at normal Console Settings widths and reflow to one column when narrowed. Full talkgroup checklists remain collapsed until edited, and overlap warnings no longer stretch beyond their text.
- **Clear RX-only source behavior.** An RX-only resource can source a one-way patch. Destinations, two-way patch members, and multi-select members must remain transmit-capable; invalid combinations are rejected before saving.
- **One patch audio owner.** Enabled patches decode only their eligible sources through a dedicated background path. The selected source is decoded for one-way patches; every member remains eligible to source a two-way patch. Multi-select members and one-way destinations do not open patch decoders.
- **Direct adaptive-jitter ingress.** Patch-source traffic enters its ordered adaptive jitter worker directly from the FNE boundary instead of waiting for UI presentation. Decoded 8 kHz PCM is then re-encoded independently for each destination, retaining cross-protocol DMR, P25, NXDN, and analog patch support.
- **Independent local controls.** Patch forwarding continues when a source card's Listen control is off. Channel volume, stereo balance, output-device selection, and system or zone speaker mute affect local presentation only; configured adaptive jitter and RX processing remain part of the patch decode path.
- **Coordinated Apple voice route.** On macOS, Apple Voice Processing now owns one shared full-duplex application route. RX, local cues, web streams, recording playback, and transmit capture use the same physical output and acoustic echo-cancellation reference. Selecting DVM Console processing switches playback and capture back to the ordinary CoreAudio route.

## Fixed

- **No duplicate patch PCM.** Listen or TAR decoding no longer feeds the same PCM alongside the dedicated patch decoder. This removes the doubled audio, short repeated segments, and jittery forwarding caused by two producers driving one destination encoder.
- **No UI-induced patch starvation.** A busy presentation thread can no longer key a patch destination before delaying or dropping the source frames needed to sustain its audio.
- **Recover failed destinations.** If a destination encoder or transport session fails, router state is released so the next source audio block can establish a fresh outbound call instead of leaving the patch logically active but silent.
- **Apply source-only edits.** Changing only the selected source of a one-way patch now rebuilds the active route immediately.
- **Avoid duplicate call starts.** Audio that arrives before an explicit source call-start observation no longer generates duplicate destination-start requests.
- **Isolate patch teardown.** Disabling a patch ends each active destination and suppresses delayed or stream-ID-rewritten FNE echoes through teardown, preventing an overlapping member from cascading stale audio into another patch. Shared targets retain isolation until every active route to that member has ended.
- **Stabilize Apple Voice Processing.** Keep Mic Warm no longer leaves a second Voice Processing output competing with normal receive playback. Stalled Apple output writes fail within a bounded interval, receive diagnostics follow the physical callback and starvation counters across shared mixer lanes, receive-route recovery starts as soon as an output pump faults, and those failures are observed cleanly.
- **Always complete Quit.** Application cleanup has a bounded deadline, so a CoreAudio stop or teardown that fails to return cannot keep the window open indefinitely.

## Safety and compatibility

DVMHost/FNE R06A00 or newer is recommended. This software is for personal, non-commercial, amateur, and educational use and must not be used in public-safety or life-safety-critical applications.

The current FNE plaintext and legacy encrypted transports are compatibility protocols, not mutually authenticated sessions. Use FNE only across a trusted network or an authenticated VPN.

Settings schema version 6, codeplug compatibility, FNE wire behavior, and native vocoder ABI version 7 remain unchanged. Existing one-way patch settings remain compatible because their first saved member is restored as the explicit source.

Patch forwarding uses decoded PCM rather than direct vocoder-codeword passthrough so source and destination protocols can differ. RX processing and adaptive jitter therefore affect patch audio, while local playback volume, balance, output route, and speaker-mute controls do not.

Automated release checks do not replace validation with the intended FNE, radio, audio devices, microphone, serial or keyboard PTT hardware, and operator workflow. Sustained one-way patch forwarding has been operator-tested with this change; other live protocol and hardware combinations remain separate acceptance work. The coordinated Apple route and bounded failure behavior have automated coverage, but Apple Voice Processing, Keep Mic Warm, Bluetooth route changes, and Quit still require live validation on the intended macOS audio hardware.
