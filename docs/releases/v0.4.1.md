# DVM Console NEO 0.4.1 — Reliability and toolbar update

This patch release hardens audio-setting changes, receive-episode teardown, and session startup while refining the responsive main toolbar introduced in 0.4.0. No codeplug, settings, or card-layout migration is required.

## Added

- A documented `DvmConsole.CodeplugValidator` developer tool for validating a codeplug without starting the desktop application.
- Focused regression coverage for audio-route rollback, asynchronous command failures, multi-stream receive completion, session-construction cleanup, and responsive-toolbar breakpoints.

## Changed

- The main-toolbar spacer now collapses before toolbar content. Clocks remain immediately to the left of Keep Mic Warm and the output controls; alert shortcuts move into **MORE** first, followed by **TONES**, with clocks retained until the narrowest tier. Breakpoints account for interface scale and multiple enabled clocks.
- Receive-episode completion now waits for every physical stream in the logical episode before completing live playback and stopping its distinct TAR recording targets.
- Audio-route application, receive-episode completion, and session-construction rollback are isolated behind focused coordinators instead of being embedded in the main view model or factory flow.
- The analyzer policy now enforces explicit exception rethrowing and focused lifetime checks for the long-lived desktop service graph.
- Developer-only FNE, audio, and media probes are explicitly documented as live validation harnesses rather than packaged applications.

## Fixed

- Applying microphone processing or device routes is transactional. If a runtime reconfiguration fails, DVM Console restores the previous route, input-processing options, and Keep Mic Warm state instead of persisting a partially applied configuration.
- Asynchronous toolbar and settings commands now contain and report unexpected failures while reliably restoring their enabled state. Expected cancellation remains quiet.
- Receive playback and TAR teardown can no longer overtake buffered packets from another physical stream belonging to the same logical receive episode.
- The Activity sidebar and Console Settings Event History now preserve the current visible call when new entries arrive above it. They continue following new calls when already at the top.
- Failed main-window construction now releases the partially built session, and recording finalization workers start only after spool recovery has completed. Cleanup failures retain the original construction error.
- Opus reader, encoder, PCM prefix stream, and serial PTT ownership paths now release transferred resources consistently when construction or decoding fails.

## Removed

- Unreachable standalone recording-catalog filter, column-visibility, and code-behind handlers. Event History, recording search, playback, reveal, retention, and deletion behavior are unchanged.
- The ambiguous developer project name `DvmConsole.App`; its supported codeplug-validation purpose is now explicit as `DvmConsole.CodeplugValidator`.

## Compatibility and migration

- No codeplug, settings, recording-catalog, or channel-card migration is required.
- Existing toolbar-clock settings and alert-tone visibility preferences are preserved.

## Validation

Local release-candidate validation passed 1,058 managed Release tests, 23 native
vocoder tests, the native CoreAudio PCM-ring test, 18 release-metadata tests, a
codeplug-validator smoke, Apple Silicon package verification, ZIP integrity,
and a LaunchServices desktop-window smoke.

These checks do not replace the final tagged workflow, which must validate every
supported package target and read back the staged release assets. Live FNE,
radio, microphone, Bluetooth, serial PTT, and sustained operator workflows
remain separate acceptance checks.
