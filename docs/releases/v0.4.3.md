# DVM Console NEO 0.4.3 — Efficiency and alert audio update

Version 0.4.3 reduces package size, idle work, and receive overhead. It also
corrects dropouts reported while transmitting generated tones and imported
alert audio. No codeplug, settings, tone asset, recording catalog, or channel
card migration is required.

## Changed

- Packages are smaller because each one carries only its target platform's audio
  and Avalonia backends. Source-generated JSON metadata, partial managed
  linking, and removal of portable debug symbols reduce the distribution size
  further.
- Audio meters stop rendering while idle and restart when a sample arrives.
  Stable default-device checks gradually back off from one to five seconds and
  immediately return to the fast interval after a route change or failure.
- Receive routing reuses decoder snapshots when routes change and avoids a new
  target array for each packet on the common single-channel path. Pipeline
  diagnostics now distinguish intentional jitter hold, worker backlog,
  session-gate waiting, clear or encrypted processing, and mixer admission.
- Debug Logs report the first jitter event, periodic updates during a long
  physical stream, and a final stream summary instead of retaining one entry per
  affected packet. Per-packet transmit, PCM-level, and routine FNE keepalive
  entries remain available through **Enable verbose logging**.
- WAV decoding reuses pooled buffers. TAR finalization keeps the durable WAV for
  retry and recovery, then encodes the retained range directly instead of
  rewriting the whole WAV first.
- Imported WAV and MPEG alert assets are transmitted through the ordinary audio
  encoder in every digital mode. Generated tones, built-in alerts, DTMF, and
  QCII continue to use their dedicated generation paths.

## Fixed

- Generated and imported alert audio now follows a compensated 20 ms frame
  schedule. Encoding and network send time no longer accumulates as pacing
  drift. If a frame runs late, transmission resumes from the current time
  instead of sending a catch-up burst. This corrects the reported dropouts in
  alert-tone and custom-asset transmission.
- P25 grant-demand traffic remains on the terminator lifecycle path because it
  requests a peer grant rather than starting voice. An accepted call begins on
  its first LDU1 while preserving that packet's 180 ms cadence and LDU2 late
  entry.
- Receive routing and diagnostics avoid steady-state per-packet collection work,
  and retained Debug Log updates are batched under the existing 100 MB session
  limit with a 50,000-entry safety ceiling.

## Compatibility and migration

- Existing codeplugs, operator settings, custom tone assets, recordings, and
  channel-card layouts remain compatible.
- Existing custom audio assets do not need to be reimported. On P25 they now use
  the same ordinary vocoder path as other imported audio instead of attempting
  single-tone detection. Explicit generated P25 tone sequences retain their
  tone-lookup path.
