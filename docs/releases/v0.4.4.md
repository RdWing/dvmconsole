# DVM Console NEO 0.4.4 — Connection, audio, and runtime hardening

Version 0.4.4 recovers more reliably from stalled FNE handshakes, puts receive
and transmit meters on the same scale, and bounds queued media work. No
codeplug, settings, recording catalog, or channel-card migration is required.

## Changed

- Receive and transmit channel meters now use the same -50 to 0 dBFS scale. The
  fill shows 50 ms RMS level with fast attack and controlled release. A separate
  peak marker holds for 750 ms and changes from white to yellow at -12 dBFS,
  then red at -6 dBFS.
- Downsampling keeps its anti-alias filter continuous across input chunks at
  integer and non-integer sample-rate ratios. This includes common 48 kHz and
  44.1 kHz device input converted to the 8 kHz radio-audio boundary. Default
  microphone processing and same-rate playback also avoid unnecessary sample
  copies.
- Channel and patch transmit queues have explicit safety limits. Engineering
  Health reports current depth, peak depth, capacity, and oldest-frame age. If
  a queue reaches its limit, Console stops the transmission rather than
  allowing delayed audio to grow without bound.
- TAR finalization remains durable on disk if its bounded worker queue is full.
  Pending jobs resume as worker capacity becomes available, without creating an
  unbounded list of in-memory tasks.
- TAR metadata now records encryption as Unknown, Clear, or Secure and keeps the
  protocol algorithm and key identifiers when they are available. New embedded
  metadata does not include machine-specific catalog paths.
- Debug Log text searches wait 150 ms for typing to settle before rebuilding
  the result set. The visible list contains the newest 5,000 matching rows while
  the existing retained-session limits and redacted export remain unchanged.
- Session composition now separates construction, restoration, event wiring,
  ownership, and teardown. CI checks application-owned formatting, dependency
  boundaries, and platform package size and file-count budgets.

## Fixed

- An FNE login acknowledgement now resets login retry pacing. If authentication
  or configuration then makes no progress for 15 seconds, Console closes only
  that system's network session, waits one second, and retries. The card status
  identifies whether authentication or configuration stalled.
- Meter colors stay fixed across the full scale. A partial reading no longer
  compresses the green, yellow, and red bands into the active fill width, and
  the peak marker uses the same yellow and red thresholds.
- CLEAR receive audio now plays on every digital channel, regardless of whether
  transmit is fixed or selectable and whether **SECURE** or **CLEAR** is
  selected. Encrypted receive audio still requires the matching key.
- Unreadable operator settings fall back to defaults. Recording-catalog scans
  count inaccessible paths and continue instead of failing the whole scan.
- Live TAR recovery snapshots are no longer mistaken for recordings that are
  ready to finalize. Completing another recording cannot close the active PTT
  capture, and a TAR storage problem is reported without terminating Console.
- Explicit encryption metadata can correct an earlier DMR clear inference. If
  an FNE reuses a stream ID after a confirmed terminator, the next definitive
  start creates a separate History and TAR call instead of combining the audio
  and security details from both calls.
- Releasing PTT stops new microphone input, sends the accepted queue at its
  normal cadence, and then completes and terminates the radio call. The channel
  queue now holds roughly one second of audio, preventing a long release or
  shutdown delay without aggressively cutting off the end of ordinary speech.
- The standard talk-permit cue no longer holds microphone audio for a fixed
  200 ms after playback drains. Cold Bluetooth startup still waits for measured
  CoreAudio presentation latency and uses its existing fallback when that
  measurement is unavailable.
- A channel cannot be keyed while it is receiving. Its PTT control becomes
  available again when the call ends, without retaining a hidden toggle latch
  or treating a click on disabled PTT as an RX toggle.
- Debug Log export writes to the save provider's file handle instead of
  requiring a local filesystem path. The status bar confirms the destination
  or reports a write failure.
- Partially constructed sessions release resources in reverse ownership order.
  Startup and shutdown cleanup no longer replaces the original failure when a
  later cleanup step also fails.

## Compatibility and migration

- Existing codeplugs, operator settings, recordings, tone assets, and
  channel-card layouts remain compatible.
- Existing Opus recordings remain readable. New recordings use the expanded
  encryption state and identifier fields without requiring a catalog migration.
- Encryption settings now govern transmit only. Fixed secure channels always
  transmit securely, and selectable channels use their saved **SECURE** or
  **CLEAR** transmit choice. Both can receive clear calls.
- The meter change affects presentation only. It does not change receive gain,
  transmit gain, vocoder levels, AGC targets, or recorded audio.
- The radio core remains at 8 kHz. The resampler changes apply only where audio
  crosses a device or media sample-rate boundary.
- This change does not affect traffic or keepalives on connected FNE sessions.
  The reconnect watchdog runs only after login advances to authentication or
  configuration; the login acknowledgement only resets retry pacing.
