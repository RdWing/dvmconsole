# DVM Console 0.1.0

This is the first public release of the cross-platform Avalonia DVM Console.
It provides self-contained packages for Apple Silicon macOS and Windows x64
while retaining the established DVM FNE and codeplug workflow.

## Highlights

- Monitor and transmit on multiple configured DVM FNE systems from one console.
- Use independent RX, TX, PAGE, ALERT, and TAR controls for each resource.
- Decode and encode P25 and DMR audio with the included native DVM vocoder.
- Mix simultaneous receive channels with per-channel volume and explicit output
  overrides.
- Use card PTT, application/global keyboard PTT, or an optional serial PTT
  device.
- Use DVM Console microphone processing on both platforms or Apple Voice
  Processing I/O with echo cancellation and AGC on compatible macOS routes.
- Send built-in alerts, custom alert audio, DTMF, generated tones, and QCII
  pages to armed resources.
- Configure patches, multi-select groups, call history, recordings, web streams,
  clocks, layouts, themes, and startup behavior from Console Settings.
- Read the current operator documentation from GitHub inside the application.

## Packages

- `dvmconsole-0.1.0-osx-arm64.zip` — Apple Silicon macOS application bundle.
- `dvmconsole-0.1.0-win-x64.zip` — Windows x64 single-file application and
  native vocoder.

The packages are self-contained; a separate .NET installation is not required.
Both builds are currently unsigned.

### macOS installation

Move `DVMConsole.app` to Applications, then remove the quarantine attribute
from the official downloaded release:

```sh
xattr -dr com.apple.quarantine "/Applications/DVMConsole.app"
```

macOS may request local-network, microphone, Accessibility, or Input Monitoring
permission as the corresponding features are first used.

### Windows installation

Extract the complete ZIP and start `DvmConsole.Desktop.exe`. Keep
`libvocoder.dll` beside the EXE. Microsoft Defender SmartScreen may warn because
the application is unsigned.

## Compatibility and limitations

- DVMHost/FNE R06A00 or newer is recommended. Older FNE builds may behave
  unpredictably.
- Codeplugs created for the original R01A00 console should be reviewed before
  use because resource configuration has changed substantially.
- Apple voice processing on macOS requires the system-default input/output pair
  or one duplex Core Audio device. Use DVM Console processing for unrelated
  split input/output devices.
- NXDN operator audio remains disabled until a compatible NXDN vocoder backend
  is available.
- Subscriber acknowledgement decoding for P25 commands is not yet implemented.
- Windows hardware audio and global-hotkey behavior should be validated on the
  intended operator workstation.
