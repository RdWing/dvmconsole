# DVM Console NEO 0.4.0 — Runtime and workflow update

This release debuts a revised Settings window, introduces responsive toolbar behavior, adds optional engineering diagnostics, and optimizes the runtimes that power DVM Console NEO.

## Added

- Searchable Settings navigation and responsive toolbar overflow. Narrow windows move clocks and secondary tone shortcuts into overflow before operational controls.
- An optional, resizable **View > Engineering Health** pane for microphone freshness, receive queue pressure, transmit backlog, recording finalization, catalog work, route recovery, and latency measurements. It is hidden by default and does not duplicate operational controls.
- Release checksums, per-package SPDX SBOMs, and artifact attestations.

## Changed

- The software identifier displayed to FNE systems is now `DVMC_NEO_0.4.0` instead of `DVMC_AV_0.4.0`.
- Operational models and receive-lifecycle decisions now live in the Avalonia-free `DvmConsole.Operations` layer. Session services have an explicit owner and disposal boundary while existing compatibility facades remain available.
- Receive processing observes each packet once through a precomputed route snapshot, uses a coalesced wake signal, and time-budgets presentation work. Tracked routing-allocation cases for 1, 10, and 100 channels are at least 80 percent lower.
- Settings writes use latest-wins snapshots and explicit flush boundaries, keeping slider-driven filesystem work off the UI thread.
- TAR metadata loading and pruning share one traversal, and recording/history catalogs use keyed linear reconciliation.
- Microphone capture is prepared before network activation, while microphone and patch audio are paced on the protocol's 20 ms clock instead of the timing of audio callbacks or decoded batches.

## Fixed

- DMR and P25 calls now send complete, mode-correct start and end sequences. This includes DMR privacy headers, P25 grant-demand handling, one P25 terminator, and the protected-service indication for encrypted P25 calls.
- Fresh FNE connections now send keepalives with a nonzero stream ID so the master can track pings before inbound voice traffic arrives.
- Patch groups now resolve the configured channel and protocol correctly, pace destination audio, and keep termination and loop suppression scoped to the actual stream. This restores cross-protocol and all-to-all patch audio, including immediate reverse calls. Patch target failures are visible in Debug Logs.
- Receive control and metadata no longer consume voice playout deadlines or missing-packet counts. P25 grant-demand control was separated from voice payload timing.
- A stalled FNE handshake now recycles only that system's connection session. Unanswered login attempts keep the normal first retry, then back off to a maximum 60-second interval until a login or explicit operator restart resets the cadence.
- TAR finalization jobs persist across restart, retry transient failures, and quarantine invalid jobs without deleting valid source recordings.
- Stale or faulted microphone capture can no longer satisfy transmit readiness.
- Cold Bluetooth talk-permit startup now uses the first post-transition microphone callback and measured output presentation latency, without a pilot or cue tail. Wired and built-in inputs retain their faster startup path.
- CoreAudio write no-progress is detected by a shared two-second watchdog without partial-write allocations.
- Local Space PTT no longer consumes Space in editable fields or ordinary interactive controls. Configured local and OS-global PTT remain available.

## Compatibility and migration

Correction: the original release notes described a grant-demand TDU as a
non-terminator. A grant demand only requests a peer grant and remains a
terminator by design. The first accepted LDU1 starts the call while retaining
its voice cadence. The receive lifecycle correction was made after v0.4.0.

- No codeplug, settings, or card-layout migration is required.
